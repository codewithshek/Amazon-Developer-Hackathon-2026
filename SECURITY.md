# SECURITY.md — Threat Model, Controls, and Known Gaps

HearthGuard is a **local hackathon demo**, not a production care system. This document
describes what the code actually does, what it does not do, and what must change before it is
exposed to a network or used with real people.

The short rule: **run it on localhost, with fictional data, and do not treat the MCP or REST
ports as authenticated.**

---

## 1. Deployment assumption

The default configuration assumes:

- one trusted machine;
- one local user;
- no untrusted network access to `:4000`;
- fictional household data;
- no real camera, lock, light, or medical device.

`npm run dev` binds the Express server to the default host interface. Do not port-forward it,
put it behind a public reverse proxy, or run it on a shared network without adding the controls
listed in §5.

---

## 2. Controls that are implemented

### 2.1 Ring-style webhook integrity

`POST /api/ring/webhook` verifies:

- presence of `X-Ring-Signature` and `X-Ring-Timestamp`;
- signature format `sha256=<64 hex>`;
- a 9–12 digit epoch timestamp;
- `|now − timestamp| ≤ 300 s`;
- HMAC-SHA256 over `<timestamp>.<raw body>` using `RING_WEBHOOK_SECRET`;
- comparison with `crypto.timingSafeEqual`.

`express.json` captures the exact raw bytes before parsing, so the signature covers what was
sent, not a re-serialized object. Invalid requests return `401`; malformed payloads return
`422`.

This is a Ring-*style* contract used by the demo. It is not claimed to be the current official
Ring Partner API signature scheme. The default secret is a public demo string; it must be
replaced for any non-local use.

### 2.2 MCP origin filtering

`/mcp` rejects browser requests whose `Origin` is not:

- absent,
- `http://localhost:*`,
- `http://127.0.0.1:*`, or
- exactly `MCP_ALLOWED_ORIGIN`.

Allowed origins are echoed in `Access-Control-Allow-Origin`; the route does not use `*`.
`Mcp-Session-Id` is exposed to browser JavaScript so the client can maintain a session.

This is DNS-rebinding/CSRF friction, **not authentication**. A non-browser client that can
reach the port can call every tool.

### 2.3 Session handling

- Session ids are UUIDs generated by `randomUUID`.
- Unknown or expired session ids return `404`.
- `DELETE /mcp` removes the session from the in-memory map.
- Sessions do not survive a restart and have no TTL.

There is no per-session authorization, ownership check, or quota. The map is unbounded for the
life of the process.

### 2.4 Request limits and headers

- JSON body limit: **256 kB**.
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `X-Frame-Options: SAMEORIGIN`
- `X-Powered-By` disabled.

There is no Content-Security-Policy, HSTS, or Helmet middleware.

### 2.5 Data minimization

- The server does **not** receive camera frames. The visible camera is procedural canvas art
  in the browser.
- The server does **not** receive microphone audio.
- WHEP is represented by an SDP negotiation result; no media is connected.
- Incidents and timeline entries are held in memory. There is no database, file write, or
  object storage for them.
- The timeline is capped at 120 entries and cleared by reset/restart. It is **not** an
  immutable audit log, and it does not record the MCP session id.
- The room tone is generated in the browser with WebAudio; no recording is streamed or
  licensed.

### 2.6 Secrets

- Secrets are read from environment variables (`.env` is gitignored).
- No AWS keys, Ring tokens, or Bee credentials are sent to the client.
- The client receives no server secrets. It does receive public capability flags
  (`live` / `replay` / `fixture` / `simulator`), fictional incident data, and a truncated
  session id.

### 2.7 Demo-mode switch

`DEMO_MODE=false` disables `POST /api/demo/trigger/:id` and `POST /api/demo/reset` with `403`.
It does **not** disable the webhook, MCP, SSE, or read endpoints. It is a demo convenience, not
a security boundary.

## 3. Threat model against the current build

| Threat | Current reality | Mitigation / residual risk |
| --- | --- | --- |
| **Spoofed webhook** | Anyone who knows the default secret can sign a request | Constant-time HMAC + 300 s window; replace the secret and restrict network access |
| **Replay of a captured webhook** | A captured body+signature is valid for up to 300 s | Timestamp window; no nonce cache, so replay inside the window is possible |
| **Malformed/tampered webhook** | Rejected before scenario processing | Format checks, raw-body verification, 401 |
| **Malicious MCP client** | No auth; any local process can call tools | Local-origin filter only; do not expose the port |
| **DNS rebinding / browser CSRF** | A malicious page could try to reach localhost | Origin allowlist; non-browser clients bypass it |
| **Session hijack** | UUID session id in a header | No auth binding; a leaked id is usable until DELETE/restart |
| **Resource exhaustion** | Large JSON, many MCP sessions, repeated tool calls | 256 kB body cap; no rate limit, no session cap, no TTL |
| **Sensitive data disclosure** | Fictional scenarios; live Bee/Bedrock could contain real data | No persistence; do not use real health data without a privacy review |
| **Camera/audio capture** | None; canvas art only | No frame pipeline to secure |
| **Unauthorized device action** | Actions are simulated strings | No real lock/light/device integration exists |
| **Credential leakage** | AWS/Ring/Bee env vars | `.env` ignored; use an IAM role/secret manager in production; rotate keys |
| **Cross-site API abuse** | `/api` uses permissive CORS | Do not expose `/api`; add origin policy and auth in production |
| **Clickjacking** | `X-Frame-Options: SAMEORIGIN` | No CSP `frame-ancestors`; add one in production |
| **Audit repudiation** | Timeline is in-memory, mutable, clearable, capped | No compliance-grade audit trail; add append-only storage with identity |

## 4. Privacy notes

The scenarios mention a fictional older adult, a Deaf resident, a dentist appointment, and
insulin delivery. That is sensitive subject matter even though the data is invented.

- Do not replace the fixtures with real health information for a public demo.
- If a live Bee proxy is connected, its spoken memory may contain real household data. Treat
  `BEE_PROXY_URL` as a sensitive integration and do not log its payloads.
- If live Bedrock is enabled, the prompt includes the scenario summary and the Bee commitment.
  Do not send real personal data to a model endpoint without consent and a retention review.
- The browser’s room tone is generated locally. It is not a recording of the room.
- The server keeps incidents in memory for the process lifetime; restarting clears them.

## 5. Required before production

At minimum:

1. **Authentication and authorization** on `/mcp` and `/api`; per-caregiver identity and
   scopes.
2. **TLS** everywhere; no plaintext MCP or API.
3. **Origin policy** for `/api`; remove `cors()` default wildcard.
4. **Rate limiting**, session caps, TTLs, and request quotas.
5. **Persistent, tamper-evident audit storage** with retention and access controls.
6. **CSRF protection** for any browser-cookie-based auth.
7. **CSP**, HSTS, and a reviewed header set.
8. **Secrets management**: IAM roles / secret manager; no static keys in env for production.
9. **Live Ring partner validation** of the signature and WHEP contract.
10. **Privacy impact review** and consent for camera, audio, health, and location data.
11. **Accessibility and safety review** with the people the system is meant to support.
12. **Dependency and container scanning** if packaged for deployment.

## 6. Reporting

This is a hackathon repository with no production deployment or security contact. If you find
an issue, open a private report with the repository owner rather than filing a public exploit
details issue. Do not test against systems you do not own.

---

## 7. What this document does not claim

- It does not claim the app is “secure.”
- It does not claim the timeline is immutable or attributable to an MCP session.
- It does not claim a zero-disk video pipeline; there is no video pipeline at all.
- It does not claim official Ring or Amazon certification.
- It does not claim the default secret, permissive `/api` CORS, or unauthenticated MCP are
  acceptable outside localhost.
